Transformer 为什么要位置编码

对于attention机制而言，本身的输入不包含位置信息。而位置信息在语言中有很重要的地位，所以我们需要通过一定的方式来表示一个序列的位置与相对位置信息。
什么是好的位置编码：应该能反应一个序列的绝对位置，也就是每一个顺序的位置编码是独一无二的；其次，相同的相对距离对不同长度序列的影响应该是相同的；编码要处处确定而且有界。

Multi-attention

2026-05-15

Self-Attention 和 Cross-Attention 的区别

self-attention：每一个词都有自己的QKV，QKV均来自于同一个序列。作用是捕捉同一个序列内上下文信息和信息依赖关系。用在模型的Encoder部分。
cross-attention：不同序列之间的注意力，Q来自序列A，KV来自序列B，除此之外，计算流程并无区别。作用是对齐两个序列的语义关系，常用在模型的Decoder部分。也是多模态中对齐不同种类信息的关节结构。

Multi-Head Attention 的作用

词向量的维数反应了一个词的某些信息。多头注意力最直观的作用，就是针对不同维度的信息单独特化，最后再拼接在一起，对信息的处理最大化。而传统的单头注意力往往只能反应最直观的维度。
从其他角度也有很直观的理解，比如类比到dropout，为系统提供了一种冗余能力，提高了鲁棒性；多头注意力有多个softmax，在单头中，我们不太允许出现极其锐利的峰值，但多头中，我们针对某个维度可能可以提取出很锋利的信息特征。

多头拆分

这个很好理解，我们设置要几个头，根据头的数量和词向量的维度，确定出每一个头的词向量维度。例子：假如我现在有1个有20token的句子，每个token的词向量有100个维度，我们设定分成4个头。拆分后，我们会得到4个20token的25维的句子。

拼接

这一步就是将加权之后的4个头的Target，重新拼回100维

线性映射

由于这四个头的内容目前关联性还不大，我们可以通过一个矩阵，让他们的信息重新交互，常见的做法是乘以一个输出权重矩阵$W^o$

多头拆分——>单头attention——>拼接——>线性映射

Attention

2026-05-15

Attention 基本原理

attention机制基本由三个基本矩阵，Q（Query），K（Key），V（Value）组成，每个矩阵都是词向量与一个投影矩阵相乘得来的，而这些投影矩阵的值，正式我们训练的目标。在attention层中，输入X经过三个不同的生成矩阵得到Q,K,V（每个词的QKV不同）。第一步，Q与K计算相关度，得到Scores，这一步评估的是每一个词与整句话的相关度程度，每个词的Q可以理解成这个词需要从别的词中获取什么信息，K可以理解成我可以为别的词提供什么信息。第二步，上一步获得的Scores经过softmax归一化，获得句子中每个词对当前词的权重系数，比如“我是中国人”中如果输入的是“人”的Q，那么权重系数中“中国”对应的系数会很大。第三步，权重系数和句子中所有的V相乘后相加，得到Z，这里V反应了每个词的含义，Z则是在这个句子中，原来词的修正的含义，称为上下文相关词向量。
attention也可以换一个角度理解，通过处理手段弱化了不值得投入资源的信息，从而节省了算力，实现了资源的动态调配。

Attention 公式推导

我们先不进行批操作，假如一个句子有n个词，输入的句子就是（n，d）的矩阵，经过$W_Q$ ,$W_K$ , $W_V$ 投影矩阵的投影，得到了Q（n，$d_k$ ),K（n，$d_k$ ),和V（n，$d_v$ )，第一步Q与K计算相关度，也就是Q$K^T$ ,获得attention scores，为了防止点积导致的方差爆炸，使数据直接大小差异过大，所以除以$\sqrt{d_k}$ 缩小方差回1（scaled），再进行softmax归一化，乘以V，就得到了Z。

为什么要 scale

如果不进行scaled，在Q$K^T$ 的时候，因为$q \cdot k = \sum_{i=1}^{d_k} q_i k_i$ ，此时的方差$\text{Var}(XY) = \text{Var}(X)\text{Var}(Y) + \text{Var}(X)E(Y)^2 + \text{Var}(Y)E(X)^2$），若$\text{Var}(q_i k_i) = 1 \times 1 + 1 \times 0^2 + 1 \times 0^2 = 1$ 则$\text{Var}(q \cdot k) = \sum_{i=1}^{d_k} \text{Var}(q_i k_i) = d_k$ ，当$d_k$ 很大时，点积之后的方差将会非常大，softmax的公式决定，大的更大，小的更小，如果分布的方差太大，权重系数会出现只有最相关的词的权重系数为1，其他的全为0.求梯度之后$\frac{\partial \mathbf{y}}{\partial \mathbf{x}} = \text{diag}(\mathbf{y}) - \mathbf{y}\mathbf{y}^\top$ ，如果只有最相关的词的权重系数为1，其他的全为0，此时梯度将会下降到0，也就是网络将失去学习能力。

建模方法

2026-05-15

加载方法： Mujoco可以读取MJCF或者URDF格式的纯文本XML文件，MJCF 和 URDF 文件使用 mj_loadXML 加载，而 MJB 文件则使用 mj_loadModel 加载。
加载过程： XML通过 TinyXML 解析器将其解析为文档对象模型（DOM），然后对该 DOM 进行处理，并将其转换为高级的 mjSpec 对象。一个有效的 XML 文件具有唯一的顶级元素。对于 MJCF，该元素必须是 mujoco；对于 URDF，则必须是 robot

编译过程： 一旦通过加载 MJCF 文件、URDF 文件或通过编程方式创建了高级 mjSpec 对象，它就会被编译成 mjModel。一旦遇到错误编译将终止，生成的错误信息包含 XML 文件中的行号和列号。解析器使用自定义的 schema（模式）来确保文件结构、元素和属性的有效性。随后，编译器会应用许多额外的语义检查。最后，对编译后的模型执行一个仿真步，并拦截任何运行时错误。后者是通过（临时）将 mju_user_error 设置为指向一个能抛出 C++ 异常的函数来实现的

保存模型： MJCF 模型可以由多个（被包含的）XML 文件以及从 XML 引用的网格、高度场和纹理组成。编译后，所有这些文件的内容会被整合到 mjModel 中，并可以通过 mj_saveModel 保存为二进制的 MJB 文件。
也可以通过 mj_saveLastXML 将编译后的 mjSpec 保存为 MJCF 格式。需要注意的是，编译后的模型无法进行结构性更改（只能改数值，不能改结构）。导出的 XML 结构可能和你最初手写的长得不一样。在导出的文件里，所有的坐标都会被强制转换为局部坐标，每一个刚体的位置、方向、惯性张量都会被毫无保留地明确写出来

MJCF建模： MJCF 文件的主体部分是由嵌套的 body 元素构成的 XML 树，顶级的 body 是特殊的，称为 worldbody。在 MJCF 中，从 XML 的角度看，子 body 就字面意义上是父 body 的子元素。
当在一个 body 内部定义 joint 时，其作用不是连接父 body 和子 body，而是在它们之间创建运动自由度。如果某个 body 内部没有定义任何 joint，则该 body 与其父 body 固连（焊接）。MJCF 中的一个 body 可以包含多个 joint，因此无需引入虚拟 body 来创建复合关节。只需在同一个 body 内部定义组成所需复合关节的所有基本关节即可。例如，可以使用两个滑块关节和一个铰链关节来模拟一个在平面内运动的 body。

默认设置

MuJoCo 根据以下优先级（从高到低）来决定物体的最终颜色：

  1. 直接定义（显式赋值）： 直接在物体标签上写的属性（如 rgba="..."）。

  2. 直接指定类（显式类）： 在物体标签上指明使用哪个 class（如 class="..."）。

  3. 父级管辖权（子类继承）： 包含该物体的父级节点指定的 childclass="..."。

  4. 全局默认： 什么都不写时，默认使用的第一个顶级 class。
    <default> 标签里定义的所有 <geom> 或 <body>，都不是物理世界中真实存在的东西，它们是“虚拟元素”（幽灵）。它们不会在仿真中产生任何碰撞、重力或渲染画面。
    如果你对 inertia 或 mass 什么都不写（处于特殊的未定义状态），编译器会利用该物体绑定的几何体（geom）的形状和密度，用微积分自动帮你推导出精确的质量和惯性张量，但如果不小心修改了，将会失去这个功能。

坐标系： 动力学树中所有坐标均是自身坐标系。如果 Body B 嵌套在 Body A 内部（B 是 A 的子级），那么 B 所填写的坐标，是相对于 A 的中心点（原点）的；几何体 (geom)、关节 (joint)、传感器测点 (site)、相机 (camera) 和光源 (light) 这些“附属组件”，它们的位置都是相对于包裹它们的那个 Body 的原点的。

坐标系朝向： 尽管底层运算都是四元数，但是mujoco提供了五种描述姿态的方式：

① quat (四元数)

  • 输入: quat="w x y z" (默认是 "1 0 0 0"，代表不旋转)。
  • 适用场景: 你已经通过代码（比如 Python 或 C++ 的数学库）计算好了旋转，直接填入即可。这是官方最推荐的方式，因为它不需要编译器做任何转换，加载最快。

② axisangle (轴角)

  • 输入: axisangle="x y z a" (代表绕着向量 旋转 角度)。
  • 物理直觉: 这非常符合刚体力学中的指数坐标（Exponential Coordinates）和右手法则。大拇指指向 向量的方向，四指弯曲的方向就是旋转方向。
  • 适用场景: 模拟单一关节的旋转（例如铰链绕特定轴转动一定角度）时非常直观。

③ euler (欧拉角)

  • 输入: euler="roll pitch yaw" (绕 X、Y、Z 轴的旋转角度)。
  • 适用场景: 最符合人类日常空间直觉的方式，常用于设置摄像机角度或初始摆放位置。
  • 注意: 旋转的先后顺序取决于全局的 compiler/eulerseq 设置（默认通常是 xyz）。

④ xyaxes (指定 X 和 Y 轴朝向)

  • 输入: xyaxes="x1 y1 z1 x2 y2 z2" (前三个数是目标 X 轴的指向，后三个是目标 Y 轴的指向)。
  • 机制: 给定 X 和 Y 后，Z 轴会自动通过叉乘（Cross-product）计算出来。
  • 适用场景: 需要极其精确地对齐坐标系时。比如要把机械臂的末端执行器（End-effector）完美对齐到桌面的某个斜面上。

⑤ zaxis (指定 Z 轴朝向)

  • 输入: zaxis="x y z"。
  • 机制: 编译器会计算一个“最小旋转”，把物体原本朝上 (0,0,1) 的 Z 轴，掰到你指定的 方向上。
  • 适用场景: 专门针对具有旋转对称性的几何体（如圆柱体 cylinder、胶囊体 capsule、球体）或者光源。比如一根圆柱体，你只关心它指向哪里，不关心它自身绕中轴转了多少度，用 zaxis 就极其方便。

总览

2026-05-13

模拟数据形式

mjModel： 包含模型描述，并应保持恒定。其中还嵌入了其他包含仿真和可视化选项的结构体，这些选项偶尔需要更改，但由用户来操作。
mjData ：包含所有动态变量和中间结果。它被用作一个草稿板，所有函数都从中读取输入并写入输出——这些输出随后成为仿真流程中后续阶段的输入。它还包含一个预分配且内部管理的堆栈，因此在模型初始化之后，运行时模块无需再调用内存分配函数。
mjModel 由编译器构建。mjData 在运行时根据给定的 mjModel 构建。顶层API也体现这种分离

Mujoco特点： 可视化的GUI；并行计算（结构岛和岛休眠）；建模语言MJCF（一种高度优化的XML）；自带宏用来生成柔性材料； 支持引擎插件

Mujoco的文件组织形式： 在抽象层，我们给MJCF或者URDF，在内存中会变成mjSpec（一个C组织体）；在底层，XML会转化成二进制文件MJB，可以提高读取速度，引擎使用的是mjModel（一种编译后的C结构体），运行时全是mjModel在跑。
mjSpec 这个 C 结构体与 MJCF 文件格式一一对应。XML 加载器解析 MJCF 或 URDF 文件，创建相应的 mjSpec 并将其编译为 mjModel。用户可以通过编程方式创建 mjSpec，然后将其保存为 MJCF 文件或直接编译。

（文本编辑器）→ MJCF/URDF 文件 →（MuJoCo 解析器 → mjSpec → 编译器）→ mjModel

（用户代码）→ mjSpec →（MuJoCo 编译器）→ mjModel

MJB 文件 →（模型加载器）→ mjModel

函数 mj_step 是顶层函数，用于将仿真状态推进一个时间步。

每个模型都有三个选项可以修改

mjOption： 该结构体包含所有会影响物理仿真的选项。它用于选择算法并设置其参数、启用或禁用仿真流程中的不同部分，以及调整系统级别的物理属性（如重力）。
mjVisual： 该结构体包含所有可视化选项。还有额外的 OpenGL 渲染选项，但这些选项与会话相关，不属于模型的一部分。

mujoco的重要概念： 物体、几何体、标记点
物体： 它是系统动力学计算的核心载体。它包含了这个零件的质量和惯性张量，在空间中是绝对隐形的，也不会和任何东西发生碰撞。
几何体： 专门负责视觉渲染（外观）和碰撞检测（物理接触），在引擎底层（编译后的 mjModel 中），几何体本身是被剥夺了质量和惯性的，它只是一层壳。
标记点： 有外观（能在屏幕上画出来），但既没有质量，也没有碰撞体积。专门用来在空间中精确标记一个位置。比如：你想在手指尖装一个触觉传感器、在头顶装一个 IMU（惯性导航）
在运动学树中，只有物体能作为节点（通过关节 Joint 与其他 Body 连接）。 几何体和标记点都被死死地“焊”在它们所属的父级物体上。当物体移动或旋转时，挂载在它身上的所有几何体和标记点都会跟着完全同步地移动。
